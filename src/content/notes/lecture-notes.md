# 第一部分 · 基础

## 语言模型到底是什么

> *"LLM 是一个非常昂贵的自动补全。"*
> —— Andrej Karpathy

大语言模型是一个**函数**。给它一些文本，它为每个可能的下一个 token 输出一个概率，挑出一个，把它接到输入末尾，然后重复。其他一切——它理解你的印象、礼貌的语气、拒绝的话术、推理步骤——都建立在这个循环之上。没有隐藏的推理引擎，没有数据库查询，只有一个在海量文本上训练过的、非常擅长猜测下一个词的超大神经网络。

### 一句话定义

> *大语言模型是一个函数：输入一个文本 token 序列，输出下一个 token 应该是什么的概率分布。*

大多数媒体报道漏掉了"概率"这个词，把模型说成一个会吐出唯一确定答案的神谕。它不是。对词表（GPT-4 约十万 token）里的每一个可能的下一个 token，模型都输出一个 0 到 1 之间的数，这些数加起来等于 1。实际打印出来的 token 是从这个分布中**采样**出来的。

![对句子"法国的首都是"的下一个 token 分布的简化视图。"Paris" 一个 token 占了约 88% 的概率质量，London、Rome、Madrid、Berlin 等相关 token 分享个位数百分比，其余约 99,990 个词表的 token 合计概率几乎为零。](/img/lecture-notes/images/next_token_distribution.png)

### 它是"分布"这一点为什么重要

"分布"这个词能推出两件事，它们解释了大量 LLM 的日常行为。

**第一，模型默认不是确定性的。** 同一个问题问两遍，答案会略有不同，因为采样器第二次可能挑中不同的 token。把温度（temperature）设为 0 可以关掉随机性，强迫采样器永远选概率最高的 token；想要更多花样也可以把温度调高。这一个旋钮造就了"准确但无聊"和"有创意但不可靠"之间的大部分差异。

**第二，模型永远不会完全确定。** 即使正确答案拿到 99% 的概率质量，剩下的总有一点落在错误答案上。提示词的微小改动就可能让概率落点移动。这就是为什么听起来很自信的答案仍然可能是错的，也为什么同一问题的细微改写有时会产生不同答案。

> **旁注：一个重要的直觉。** 当你听说"模型选了一个词"时，实际发生的是：模型为词表里的每一个 token 都生成了一个概率，然后由一个独立的采样步骤挑出一个。温度 0 时，采样器永远选最大值；温度 0.7 时，随机性变大，偏向头部 token 但偶尔选中出人意料的；温度 1.5 时，在头部几个 token 之间几乎均匀；再往上，输出通常退化为乱码。

> **本章要点**：LLM 是一个函数，输入文本，输出下一个 token 的概率分布。你在 ChatGPT 里看到的对话，就是这个函数被反复运行、每次把采样出的 token 喂回去的结果。其他一切——语气、人格、拒绝、推理——都建立在这一个循环之上。

## 一张图看懂训练流水线

> *"预训练是读教科书。微调是看老师做例题。强化学习是自己做习题。"*
> —— 改述自 Karpathy

训练一个对话式 LLM 分三个先后阶段。每个阶段有自己的数据、自己的目标、自己的算力预算。关键在于：算力预算每一步大约缩小两个数量级。预训练是几千张 GPU 上跑几个月；微调是几百张 GPU 上跑几小时；强化学习视具体路线而定，是几十张 GPU 上跑几天。

![三阶段训练流水线。预训练：基座模型学会英语和世界知识，几千张 GPU 上跑数月——"读教科书"；微调：基座模型学会表现得像有用的助手，几百张 GPU 上跑数小时——"看老师做例题"；强化学习：助手学会推理，几十张 GPU 上跑数天——"自己做习题"。底部的"上学"类比是 Karpathy 解释三者差异时最爱用的说法。](/img/lecture-notes/images/training_pipeline.png)

三个阶段是各自独立发展出来的。到 2022 年前后为止只有预训练这一步；那年年底让 ChatGPT 成为可能的，是对人类书写对话的微调；而大规模应用于推理的强化学习新到什么程度呢——它产出第一个被广泛讨论的模型 DeepSeek-R1，距离 Karpathy 录制这场讲座只有两周。

在前沿实验室，三个阶段分属不同团队：预训练团队负责收集清洗数据、训练基座模型；微调团队撰写示例对话，把基座模型变成助手；强化学习团队搭建奖励信号和练习环境。模型在这些团队之间按顺序交接，一个前沿模型的完整发布周期可能要花掉大半年。

> **本章要点**：LLM 训练分三个阶段，按序进行；每个阶段的输出是下一个阶段的输入；每个阶段的成本大约是前一个的百分之一。第二部分讲阶段 1，第三部分讲阶段 2 和 3。

# 第二部分 · 预训练：阅读互联网

## 训练数据从哪里来

> *"把垃圾过滤掉之后，互联网其实没那么大。"*
> —— 改述自 Karpathy

我们所说的一个 LLM 的"知识"，大部分是在预训练阶段压缩进模型的。所以预训练数据的质量是整条流水线上最重要的事。它也是最不性感的活儿：得有人把互联网下载下来，滤掉胡说八道，把剩下的打包成神经网络能吃的形态。

### Common Crawl：装进盒子里的原始互联网

从 2008 年起，一家叫 **Common Crawl** 的非营利组织运行着分布式网络爬虫：从几个种子 URL 出发，跟随找到的每条超链接，遵守 `robots.txt`，把碰到的每个页面的原始 HTML 存下来。创始人是 Gil Elbaz——他更广为人知的身份是 Applied Semantics 的联合创始人，那家公司被 Google 收购后成了 AdSense。Common Crawl 是 501(c)(3) 非营利组织，数据免费。

数字很惊人。截至 2024 年，Common Crawl 已索引超过 2500 亿个网页，每月新增 30 到 50 亿页；压缩归档总量超过 9.5 PB，存在 Amazon S3 上。从 GPT-3 开始，几乎所有公开已知的大模型都是从它的一个子集出发训练的。

原始的 Common Crawl 没法直接用。HTML 里全是导航菜单、Cookie 横幅、广告、评论垃圾、重复内容，以及一百多种语言的文本。直接喂给模型既浪费又有害。每家实验室都会把它通过一长串过滤清洗步骤，才让第一个 token 碰到网络。这些流水线在大多数实验室是专有的，但 2024 年 4 月 Hugging Face 公开了一个开源版本。

### FineWeb：清洗过的开放数据集

**FineWeb** 是 Karpathy 能在讲座里展示这一阶段的原因：它是 OpenAI、Anthropic 和 Google 内部流水线的完全开源、完全文档化的复现。数据集论文是 *The FineWeb Datasets: Decanting the Web for the Finest Text Data at Scale*（Penedo 等，2024）。

全部过滤完成后，FineWeb 约 **44 TB** 清洗后的文本，按 token 计（用 GPT-2 分词器）是 **15 万亿 token**。论原始存储，它装得进一块消费级硬盘。这是第一次听说时最让人意外的部分：互联网浩瀚，但上面有用的、不重复的、非模板化的文本并没有那么多。去掉导航标记、重复的 Reddit 评论、机器翻译的垃圾和色情内容之后，剩下的是几十 TB。

#### 过滤流水线

过滤是一串专门步骤的级联，每一步移除一类特定的垃圾。

![FineWeb 过滤流水线：PB 级的原始 Common Crawl HTML 从顶部进入，依次经过 URL 黑名单、Trafilatura 正文抽取、语言过滤、质量过滤、MinHash 去重、隐私信息移除六道关卡，约 99% 的内容在到达底部之前被丢弃，产出 15 万亿 token（44 TB）的 FineWeb。](/img/lecture-notes/images/fineweb_pipeline.png)

过滤器的顺序很重要。URL 级封锁最先发生，因为它最便宜：整域名拒绝，一个页面都不用下载。用 *Trafilatura*（一个最初为数字人文研究写的 Python 库）做正文抽取更贵，但能抢救出朴素 HTML 剥离会毁掉的材料。语言过滤用 FastText（Facebook Research 的简单分类器），英语阈值 0.65，低于阈值的文档进其他语言数据集或被丢弃。质量过滤器来自两篇更早的论文：DeepMind 的 Gopher（检测重复文本的启发式规则）和 Google 的 C4（一串更长的红旗规则，比如不以标点结尾的句子）。去重是整条流水线里最出人意料的一环，因为它删掉的东西远比你想的多——互联网的重复程度远超表面印象。

#### FineWeb-Edu：更小更干净的子集

FineWeb 一个很有用的副产品是 **FineWeb-Edu**：1.3 万亿 token，大致是 FineWeb 按"教育质量"排序的前 9%。Hugging Face 用 Llama 3 70B 给 50 万份文档打 0-5 分训练了一个回归分类器，然后用它只保留 3 分以上的文档。仅最后这轮分类就花了约 **6000 个 H100 GPU 小时**。Karpathy 建议训练较小模型时用 FineWeb-Edu——需要学到真知识，又不想被噪音淹没。

> **旁注：体量的直观感受。** 一台现代消费级 NAS 能装下全部 44 TB 的 FineWeb；一块中端笔记本固态硬盘能装下 FineWeb-Edu。人们想象"从零训练 LLM"时，脑子里通常是占满一个街区数据中心的画面——对 GPU 来说这画面没错，但**数据本身**装得进一个鞋盒。

> **2026 年 4 月更新。** Karpathy 拍摄时（2025 年 2 月），训练数据的故事大体还是"收集网页文本、清洗、去重"。之后十四个月里，两件事明显变了。
>
> **合成数据成了一等原料。** 微软的 *Phi-4*（2024 年 12 月）约 40% 的训练数据是更大模型生成的、经过课程工程设计的合成数据。Llama 3 的 15 万亿 token 混合数据里早已包含合成代码和数学。前沿实验室现在公开把预训练数据描述为"过滤后的网页文本 + 精心生成的合成提示"的**混合物**，而不是纯网页文本。不好听的真相是：只用网页垃圾训练的模型会到达平台期；网页垃圾**加上**教科书级合成数据的模型能继续扩展。
>
> **教育质量分类器普及了。** FineWeb-Edu 是 2024 年的新招。到 2026 年，几乎每个开放数据集都有同样方式过滤的"edu"或"quality"变体——Dolma 2、Nemotron-CC（NVIDIA，2024）、FineWeb-2（多语言）。大方向是：文本更少，*有用*的文本更多。

> **本章要点**：现代 LLM 的训练数据来自对 Common Crawl 的过滤流水线。Hugging Face 的开源 FineWeb 数据集是最清晰的公开样本：15 万亿 token、44 TB——丢弃掉 Common Crawl 原始内容的大约 99% 之后。

## 文本如何变成数字

> *"模型看到的不是字母，是 token。光是这一点就解释了大约三分之一的诡异行为。"*
> —— Karpathy

神经网络处理的是数字，不是字母。任何文本喂给模型之前，都得先转成整数序列。这一步叫**分词（tokenization）**，无视它会带来数量惊人的 LLM 怪异行为。

### token 不是词

**token** 是一小段文本，在固定词表里有唯一的整数 ID。GPT-4 的分词器（`cl100k_base`）的词表有 **100,277** 个 token。这个数字不是随便定的：token 太少，序列就长、处理就慢；太多，网络的输入输出层就会膨胀。10 万是个能用的折中。

token 既不是字符也不是词。非常常见的词比如 *the* 有自己的 token；不常见的词或带奇怪标点的会被切碎。用真实的 GPT-4 分词器举几个例子：

| 文本 | token | 数量 |
|---|---|---|
| `hello` | `[hello]` | 1 |
| ` hello`（带前导空格） | `[ hello]` | 1 |
| `Hello` | `[Hello]` | 1 |
| `hello world` | `[hello][ world]` | 2 |
| `unbelievable` | `[un][believ][able]` | 3 |
| `strawberry` | `[straw][berry]` | 2 |
| `antidisestablishmentarianism` | `[anti][dis][establish][ment][arian][ism]` | 6 |

注意带前导空格的 token。在 GPT-4 分词器里 `"hello"` 和 `" hello"` 是不同的 token。听着像细节，其实关系重大：分词器学到的是句子中间的词通常前面有空格，于是把这个空格直接烤进了 token 本身。

### Strawberry 问题

著名的"strawberry 里有几个 r"问题就出在这里。

![strawberry 一词的分词。人眼看到十个字母（三个 r 高亮标出）；模型看到的却是两个不透明的整数 ID——「straw」= 101637、「berry」= 70482——没有任何办法检查这两个 ID 是从哪些字母构建的。](/img/lecture-notes/images/strawberry_tokens.png)

问老一点的 LLM 这个问题，它常常答"两个"。模型不是笨。它是字面意义上**看不见**单个字母：它手里的全部信息就是两个不透明的整数 ID。数 token 里的字母，就像让你数一个你只见过整体字形的汉字有多少笔——数不了。

推理模型绕过这个问题的办法是先把单词用空格拆开写（`s t r a w b e r r y`）再去数。这强制了一种完全不同的分词，每个字母真的各自成为 token。OpenAI 第一个推理模型的内部代号，恰如其分地，就叫"Strawberry"。

### 9.11 vs 9.9 的 bug

一个相关的 bug：问 LLM 9.11 和 9.9 哪个大。很多模型自信地答 9.11，错了。原因有两个。

**第一**，字符串 `9.11` 在训练数据里作为日期（9 月 11 日）、软件版本号、圣经章节（约翰福音 9:11）出现的频率，远高于作为小数。模型内部对这个字符串的关联指向日期和版本，不是数字。

**第二**，分词把两个数切成了不同的序列：`9.11` 可能切成 `[9][.11]`，`9.9` 切成 `[9][.9]`。模型比较的是不同的 token 序列，不是等值的数值——比较发生在"token 空间"里，而 token `.11` 在嵌入空间里离 `.10` 比离 `.9` 更近。

这两个 bug 都是一句提醒：*模型看到的文本，不是你看到的文本。*

### 词表是怎么造出来的

构建分词词表的算法叫 **Byte Pair Encoding（BPE，字节对编码）**，一段话就能讲清：从 256 个字节的全量词表开始（每字符一个 token）；扫描训练文本，找出最高频的相邻 token 对；把这一对合并成新 token 加入词表；重复，直到词表达到目标大小。GPT-4 就是这么合并 100,277 次。

因为 BPE 偏爱*高频*对，它会自己发现常见词（*the*、*and*、*ing*）和常见前后缀（*un-*、*-tion*），不需要任何人告诉它什么是"词"。罕见或生造的字符串会被漏下去、切成小块。*unbelievable* 变成 `[un][believ][able]`：三个大 token 而不是十二个单字符 token，给模型省了大量工作。

> **旁注：自己试试。** 打开 [tiktokenizer.vercel.app](https://tiktokenizer.vercel.app/)，下拉框选 `gpt-4o` 分词器，随便输入一句话。你的文本会逐个 token 亮起，带整数 ID。这就是 Karpathy 讲座现场用的那个网站。输入你自己的名字、一个 emoji、一个编程语言关键字、一个故意拼错的词——规律会自己浮现。

> **2026 年 4 月更新。** Karpathy 全程用 GPT-4 的 `cl100k_base`（约 100,277 token），因为它是 2025 年初的前沿分词器。更新的模型已经转向更大的词表：GPT-4o 的 `o200k_base` 约 20 万 token，Gemini 2.0 用 25.6 万，Llama 4 定在 12.8 万。取舍和 Karpathy 讲的一样：词表更大意味着每句话 token 更少、每个 token 的网络工作量更小，代价是嵌入表大得多。实际收益对非英语语言巨大——在 `cl100k_base` 下，阿拉伯语、印地语、中文的同样内容要花 2 到 5 倍的 token；在新分词器下差距大幅缩小。
>
> Strawberry 和 9.11 这两个 bug 在推理模型里都*更少见*了（见第 12 章），因为模型学会了数数前先把字母逐个写出来。底层 bug——token 不透明——没有变。

> **本章要点**：神经网络看到任何文本之前，文本先被切成几个字符一段的 token，每个 token 是一个不透明的整数 ID。模型永远看不见 token 里面的字母——这就是它数字符数困难、对没以小数形式见过的数字翻车的原因。发生怪事时，这是最有用的一个心智模型。

## 神经网络

> *"架构和 2017 年一模一样，只是大了太多。"*
> —— Karpathy

有了分好的数据集，还需要一个能学会预测下一个 token 的神经网络。所有人用的架构叫 **Transformer**，出自 2017 年 Google Brain 的论文《Attention Is All You Need》。2018 年以来每个公开已知的主流 LLM，从 GPT-2 到 DeepSeek-R1，都是同一个设计的变体。

### 神经网络是带旋钮的函数

在讲 Transformer 特别在哪之前，快速回顾一下。神经网络是一个函数：数字进去，穿过一层层计算（每层做些乘法、加法和一个简单的非线性弯折），数字出来。内部有大量"旋钮"——术语叫**参数**或**权重**。训练就是喂示例输入、把输出与正确答案对比、然后把每个旋钮朝"本可以减小误差"的方向轻轻拧一点。

![一个小型前馈神经网络。输入值从左侧进入，流经两个隐藏层，从右侧输出。每条箭头都是一个训练过程要调整的权重。真实 LLM 堆几十层这样的结构、有数千亿个权重，但图是同一张。配图：Cburnett，CC BY-SA 3.0，via Wikimedia Commons。](/img/lecture-notes/images/neural_network.png)

拧旋钮的算法叫**梯度下降**：用微积分算出每个旋钮应该朝哪个方向、移动多少才能减小误差。在足够多的样本上做足够多次，旋钮就停进一个让网络有用的配置里。

现代 LLM 的旋钮数量在几十亿到万亿级。GPT-2（2019）有 15 亿；GPT-3（2020）有 1750 亿；GPT-4 据传接近一万亿（OpenAI 从未确认）；Llama 3.1 最大的开放权重模型有 4050 亿，技术报告说用了超过 16,000 张 H100 训练。

### Transformer

Transformer 是一种特定的旋钮排布方式，让网络擅长处理 token 序列。真正需要理解的三个概念是**嵌入（embedding）**、**注意力（attention）**和**残差流（residual stream）**，其余是配套机械。

![完整的 Transformer 架构。token 以整数 ID 从底部进入，在嵌入表中查表，穿过一叠 Transformer 块（每块含一个注意力层和一个前馈层），在顶部投影到词表上，产生下一个 token 的概率。配图：dvgodoy，CC BY 4.0，via Wikimedia Commons。](/img/lecture-notes/images/transformer_full.png)

#### 嵌入：token 是空间中的方向

网络收到一个 token 后做的第一件事是查大表。token 42 映射到一个特定向量，比如 4,096 个数。这个向量是网络对这个词元*含义*的内部表示，叫**嵌入（embedding）**。

这些向量起始是随机的，但训练中会漂移到这样的位置：含义相近的 token 距离近，含义不同的距离远。

![极简化的二维词嵌入示意。训练中模型发现 *king*、*queen*、*man*、*woman* 构成矩形的四个角：横轴（dim 1）编码类似"王室性"的东西，纵轴（dim 2）编码类似"性别"的东西。真实嵌入有数千个维度、多得多的语义轴，但原理相同：含义成为高维空间中的一个方向。](/img/lecture-notes/images/word_embeddings.png)

word2vec 时代有个经典结果：*king* 的向量减去 *man* 的向量加上 *woman* 的向量，落点极其接近 *queen* 的向量。没人告诉过模型性别是什么，它自己学会了性别的概念。

#### 注意力：看向其他 token

**注意力（attention）** 是 Transformer 的核心思想。序列里的每个 token 在被处理时，可以决定哪些其他 token 与自己相关，并按相关程度加权合并它们的表示。

看这句话："The animal didn't cross the street because it was too tired."（那只动物没有过马路，因为它太累了。）网络处理 *it* 这个词时，注意力让它注意到 *it* 最可能指 *the animal* 而不是 *the street*。这种指代消解过去需要专门算法；在 Transformer 里，它直接从训练中涌现。

机制上，每个 token 产生三个向量：**query（查询）**、**key（键）**、**value（值）**。query 与 key 匹配产生注意力权重；权重再用来加权混合 value。

![单个注意力头。每个 token 产生 query Q、key K、value V。点积 QKᵀ 给出原始注意力分数，softmax 把它们变成和为 1 的权重，再用这些权重对 value 求平均。配图：dvgodoy，CC BY 4.0，via Wikimedia Commons。](/img/lecture-notes/images/attention_block.png)

实践中 Transformer 用的是**多头注意力（multi-head attention）**：多个独立的注意力头并行运行，输出拼接起来。不同的头会分化出不同类型的关系专长：有的盯句法邻居，有的盯语义亲属，有的不管内容只盯句中特定位置。

![多头注意力。多个独立注意力头并行运行，输出拼接后投影回模型的隐藏维度。据信 GPT-4 每层有几十个头。配图：dvgodoy，CC BY 4.0，via Wikimedia Commons。](/img/lecture-notes/images/multihead_attention.png)

#### 残差流：思绪之河

Karpathy 描述 Transformer 内部发生什么时最喜欢的比喻，是想象一条从输入流向输出的信息之河。他称之为**残差流（residual stream）**。每一层从河里读取、做点计算、把结果加回河里。河在向上流动的过程中被逐步精炼，到顶部时携带的信息已足以预测下一个 token。

![单个 Transformer 块：一个注意力子层加一个前馈子层，各带一条把输出加回主流程的残差（跳跃）连接。现代 LLM 堆叠 24 到 128 个这样的块。配图：dvgodoy，CC BY 4.0，via Wikimedia Commons。](/img/lecture-notes/images/transformer_block.png)

### 一个值得花时间的交互式版本

如果你是第一次接触 Transformer，我知道的最好资源不是论文也不是教材，而是 Brendan Bycroft 做的交互式 3D 可视化 [bbycroft.net/llm](https://bbycroft.net/llm)。默认演示是一个 **85,584 参数**的微型 Transformer，训练任务是把 A、B、C 三个字母排序。它比 GPT-4 小七个数量级，但架构是同一个。你可以一个 token 一个 token 地点进去，看每一次矩阵乘法实时发生。Karpathy 在讲座里走了它一遍；你若有 40 分钟，值得坐下来玩。

回头看，Transformer 真正令人惊讶的地方在于：2017 年以来架构几乎没变。过去五年不是架构革命，是**规模和数据**的革命。把 2018 年最先进的那个 Transformer 拿来，做大，喂更多文本，你从没设计过的能力就不断自己涌现。这是现代 AI 核心处那个奇怪至今未被完全理解的事实。

> **2026 年 4 月更新。** 到 2026 年 4 月，Transformer 仍是每个前沿模型的骨干，但讲座之后有两个改进成了主流。
>
> **专家混合（Mixture-of-Experts，MoE）** 是更大的故事。块里不再是每个 token 都要穿过的一个大前馈层，而是许多更小的"专家"前馈层加一个小路由器，每个 token 只挑其中两到四个。DeepSeek-V3（2024 年 12 月）总参数 **6710 亿**，但每 token 只激活约 **370 亿**。Llama 4 Maverick 和 Mistral Mixtral 在不同规模上用同一思路。GPT-4 长期被传是 MoE，Llama 4 证实了 MoE 现在是前沿标配。洞见在于：参数量和每 token 算力可以解耦——你可以让模型变大而不让 GPU 账单成比例变大。
>
> **状态空间替代架构**是更安静的故事但值得知道。*Mamba* 和 *Mamba-2*（Dao 与 Gu，2023-2024）用线性时间的状态空间更新替代注意力，处理超长上下文更高效。*Jamba*（AI21，2024）和 *Samba*（微软，2024）是 Transformer+Mamba 混合架构。它们今天在长上下文上有竞争力，但还没在前沿取代纯 Transformer。
>
> 本章的核心信息仍然成立：嵌入、注意力、残差流。MoE 是前馈层内部的改良，不是架构重写。

> **本章要点**：Transformer 是一种特定的神经网络层堆叠方式，让网络能对 token 序列做"推理"。嵌入把每个 token 变成向量；注意力让每个 token 看向所有其他 token；残差流把信息从网络底部送到顶部。魔力来自规模：2017 年以来架构几乎没变。

## 训练基座模型

> *"就是：预测下一个 token。其他一切都是副作用。"*
> —— Karpathy

有了分好的数据集和 Transformer 架构，实际的训练过程近乎无聊。

### 训练循环

从数据集取长长的一段文本，选一个比如 4,096 个连续 token 的窗口，告诉网络："给你前 4,095 个 token，你对第 4,096 个的概率分布是什么？"把网络的答案和真实的第 4,096 个 token 对比，差值变成一个**损失（loss）** 值。梯度下降把所有旋钮朝"本可以减小这个损失"的方向拧一点。窗口向前滑动一个 token，再来一遍。重复数万亿次。

![预训练循环：一个 token 窗口从数据集进入 Transformer，模型产出下一个 token 的分布，损失衡量预测错得多离谱，梯度下降把每个参数朝"下次减小损失"的方向拧一点，重复数万亿次。](/img/lecture-notes/images/pretraining_loop.png)

### 为什么这个简单得出奇的目标能成

预训练的目标一句话就能说完：*让模型分配给真实下一个 token 的概率尽可能高，对数据集全部 15 万亿 token 取平均*。就这样。没人告诉模型什么是语法、什么是事实、什么是算术、什么是代码、怎么推理。基座模型的一切能力，都是"擅长预测人类写的文本里下一个词"的副作用。

> **旁注：为什么这出人意料。** 对这么简单的目标，涌现出的行为离谱得很：语法、翻译、逻辑、代码、诗歌、幽默、世界知识、算术……都是"拼命预测一大堆文本的下一个词"的副产品。没人完全理解为什么规模能不断解锁新能力，只知道它确实能。

这里有一个略让人不安的推论。模型不像你那样记忆事实。它在构建一个唯一用途是预测下一个 token 的世界内部表示。事实、语法、风格、人格、偏见、错误——全部由训练数据烤进去。预训练数据 70% 是英语，模型英语就会比其他任何语言强得多；里面 Python 多，它 Python 就比 Haskell 强。**训练数据的分布就是能力的分布。** 而且因为这个数据集是 44 TB 没有人真正读过的文本，没人完全知道里面有什么。

### 基座模型实际长什么样

预训练结束后你得到一个**基座模型（base model）**。它不是聊天机器人，不是助手，它是一个*文档模拟器*。给它一个文档的开头，它按开头暗示的风格续写。

- 给它维基百科式的开头，它用维基百科式的文体续写。

- 给它莎剧的前几行，它产出听起来像莎士比亚的东西。

- 单独给它"What is 2 plus 2"，它可能会做怪事，比如继续写更多问题——因为孤立的问题不是基座模型有太多续写经验的文体。它见的问题大多在问答页里，而问答页总是带着答案。

你可以在 [app.hyperbolic.xyz](https://app.hyperbolic.xyz/) 上玩真实的基座模型，那是极少数提供无过滤基座模型（具体是 Llama 3.1 405B base）的托管服务。第一次试，体验是错乱的：感觉像一个难用得多的 ChatGPT——因为它从没被训练过对话。这正是下一个阶段要解决的问题。

> **2026 年 4 月更新。** Karpathy 用"GPT-4 世代"做参照：约 1 万亿参数、约 12 万亿训练 token。规模继续在移动：Llama 3.1（2024 年 7 月）4050 亿参数、15 万亿 token；Llama 4 Behemoth（2025，未公开发布）据传约 2 万亿参数；GPT-5（OpenAI，2025 年 8 月）估计训练算力约为 GPT-4 的 10 倍；DeepSeek-V3（671B 总参 / 37B 激活，MoE）硬件时成本不到 600 万美元——说明高效配方能追平与前沿实验室的大部分差距。
>
> 底层循环——预测下一 token、对误差做梯度下降——没变。变的是数据量（现在混入合成数据，见第 3 章更新）、算力量，以及架构把参数量与每 token 工作量解耦的巧妙程度（见第 5 章更新的 MoE）。

> **本章要点**：预训练就是把一个简单循环运行数万亿次：预测下一个 token，度量误差，微调权重。LLM 的每一种能力——语法、知识、算术、编码——都是把这一件事做得极好的副作用。产出是一个*基座模型*：一个文档模拟器，还不是助手。

# 第三部分 · 后训练：成为助手

## 监督微调（SFT）

> *"微调就是把文档模拟器变成表现得像有用助手的东西。"*
> —— Karpathy

监督微调（Supervised Fine-Tuning，SFT）是基座模型不再是文档模拟器、开始像有用助手那样表现的阶段。它远不如预训练性感，也远没有预训练贵：一次完整预训练要几个月、花数千万美元；微调在很小一部分硬件上几小时就能完成。

### 配方

流程本身简单得近乎尴尬。雇一个团队写几千段示例对话：每段有用户消息（真实用户可能问的）和助手回复（一个周到、博学、礼貌的助手会说的）。然后用和预训练**一模一样**的下一 token 预测目标，在对话上微调基座模型。

架构没有任何改动，训练循环也没有任何根本改动。改的是模型要模仿的文本**分布**：不再是随机的互联网文档，而是礼貌、有帮助、切题的助手回复。因为梯度下降是一台无情的模仿机器，几小时之内模型就变成了那样。

### 环里的人

写这些对话的是受雇的承包商，不是志愿者。最早的 *InstructGPT* 论文（Ouyang 等，2022）对此很坦白：OpenAI 雇了约 40 名标注员，给了详细书面指南，规定"好"的助手回复长什么样——要友好、准确、愿意说"我不知道"、愿意明确拒绝不当请求、不愿意编造。

过去几年每家大实验室都把这套动作扩到数千名标注员，并开始专业化：编码对话由精通相关语言的标注员写，医疗对话由护士和医生写，法律对话由律师写。某个前沿模型用了多少标注员几乎没有公开数据，但 InstructGPT 论文是个有用的锚点：**40 名标注员，工作几个月，产出 13,000 段示范对话**——这就足以让 GPT-3 变成人类在正面对比中更偏好的模型，压过 1750 亿参数的原基座。

> **注意：一个令人不适的推论。** 模型的"人格"不是它自己的，是标注员们人格的平均值，再被指南塑形。当 ChatGPT 说"我是 OpenAI 训练的大语言模型，我没有感情，但是……"时，它不是在报告内在状态，它在预测下一个 token——而下一个 token 恰好是它在微调数据里见过几千次的措辞的一部分。

### 对话格式

对语言模型来说，对话仍然只是 token 序列，需要某种约定来标记一个说话者的回合在哪里结束、另一个从哪里开始。大多数实验室用**特殊 token**。一段典型对话展开成 token 形式是这样：

```text
<|im_start|>system
You are a helpful assistant.<|im_end|>
<|im_start|>user
What is the capital of France?<|im_end|>
<|im_start|>assistant
The capital of France is Paris.<|im_end|>
```

`<|im_start|>` 和 `<|im_end|>` 这两个 token 在基座模型词表里不存在，是微调时加进去的，同时配了几行专用嵌入。模型通过反复的例子学到：`<|im_end|>` 意味着"停止生成，把回合交还给用户"。现代聊天界面给你展示逐条消息的对话时，幕后真正做的事是接收模型输出的 token 流，每当 `<|im_end|>` 出现就截断。

> **旁注**：`im` 前缀是 "imaginary monologue" 的缩写——继承自 OpenAI 内部聊天格式 ChatML 的一个难听名字，后来成了各实验室的事实标准。除了最老的那批，每个模型都认它的某种变体。

> **2026 年 4 月更新。** Karpathy 讲的 SFT 故事仍然是助手获得人格的方式，但"偏好训练"环节有一个重要改进。讲座里第二味药是 RLHF——训练奖励模型、用 PPO 优化。2024 年以来，多数前沿和开源模型换成了**直接偏好优化（DPO）** 及其近亲（KTO、IPO、ORPO）：给定一对答案（一个被偏好、一个不被），DPO 用一个简单的分类损失直接调整策略，完全扔掉了奖励模型阶段。数学上它在极限下等价于 PPO 设定，但运行起来简单得多。Llama 3、Claude、Gemma、Mistral 和大多数开源微调的偏好训练现在都用 DPO 或其变体。带 PPO 的 RLHF 仍用在奖励信号天然可验证的场景——代码测试、数学答案——这正是第 9 章推理模型故事的种子。

> **本章要点**：监督微调在一小批人类书写的示例对话上训练基座模型；架构不变，变的只是训练数据。模型的语气、人格、拒绝的意愿来自对标注员的模仿。聊天格式用 `<|im_start|>` 这类特殊 token 分隔回合。

## 幻觉，以及如何驯服它

> *"模型知道自己不确定，只是没被训练过要告诉你。"*
> —— 改述自 Karpathy

语言模型**产生幻觉（hallucinate）**，是指它产出听起来自信流畅但事实上错误的内容。幻觉的谱系从尴尬（引用不存在的论文，连页码都编得像模像样）到危险（自信地说错药物剂量）。今天，它是把 LLM 用于任何要紧之事的最大障碍。

> **注意：不要相信自信的具体性。** 如果模型对某件冷门的事给出一个非常精确的说法（日期、页码、引文、URL），这恰恰是最可能编造的那类答案。自信的模糊通常是真的知识；对不寻常之物的自信精确通常是幻觉。

### 幻觉为什么发生

三个原因叠在一起。

**第一，训练数据是用自信的口吻写的。** 没有人发文章开头写"下面的内容我不太确定，但是……"。互联网上全是听起来很确定的人。基座模型学到的是：好文本看起来很自信。

**第二，微调标注员通常会把交给他们的问题答出来**，哪怕为了答题他们自己都得现查。一个不知道某道冷知识答案的标注员，承受着一种无声的压力：去查一个答案，而不是写下"我不知道"。于是微调后的模型也学到：被问问题时，产出一个自信的答案。

**第三，模型没有关于自身不确定性的显式信号。** 几乎可以肯定，模型内部有某种不确定性表示——会的问题上某些神经元更亮，不会的没那么亮。但它的训练从来没有因为"把这个表示用起来"而奖励过它。

### Meta 的修法（来自 Llama 3 论文）

*Llama 3* 技术报告（Dubey 等，2024）描述了一个漂亮的绕法：制造正确答案就是"我不知道"的训练样本。做法：

1. 从预训练数据里取一段富含事实的片段。

2. 用模型自己对这段片段生成事实性问题。

3. 另外在不给模型看片段的情况下，采样它对这些问题的回答。

4. 用模型自己当裁判，把回答与原始片段对比。

5. 对模型持续答错的每个问题，新增一条微调样本，理想回复是"我不太确定这个"。

日积月累，模型学会把内部的不确定性信号与显式的拒绝短语配对。它学会了自己无知的*形状*。

这不能根除幻觉，但帮助很大——大致解释了为什么新模型比 2022 年代的模型更愿意承认自己不知道。

### 另一个大修法：工具使用

第二类修法是给模型接上**工具**：计算器、代码解释器、网页搜索、数据库查询。通过微调样本教会模型发出特殊 token，运行时拦截这些 token、替换成真实工具输出。这把知识问题（"苹果 2024 年 3 月 14 日收盘价多少？"）转化成阅读理解问题（"这是金融数据库的答案；总结一下"）——后者模型擅长得多。

数学同理：模型需要给两个大数相乘的任何时候，都应该把活外包给计算器，而不是在脑内硬算。ChatGPT 现在遇到数值问题会自动这么做——这是它 2025 年的算术比 2023 年好得多的原因。

> **2026 年 4 月更新。** 2026 年 4 月幻觉仍是真问题，但已大幅改善。三个进展改变了局面：
>
> **检索增强生成（RAG）成为主流。** 大多数企业部署现在先生成前检索相关文档，把"从参数里回忆"变成"对检索到的文本做阅读理解"。这类部署直接消灭许多类事实性幻觉。
>
> **推理模型自我检查。** 第 9 章更新里谈的推理模型（o1、DeepSeek-R1、Gemini 2.5 Pro thinking、开扩展思考的 Claude）习惯先写出中间步骤、在给出最终答案前抓出自己的错误。不完美，但在可验证任务（数学、代码）上幻觉少得多。
>
> **带来源的回答成了标配。** Claude、ChatGPT Search、Perplexity、Gemini Deep Research 默认为事实性断言给出来源，模型被训练成找不到可依据的引用就缄口。用户可以查脚注。
>
> 底层的统计论证没变：被训练来产出"听起来可信的文本"的模型，有时就会产出"可信但错误"的文本。我们只是在它外面包了更好的护栏去接住常见失败模式。

> **本章要点**：幻觉来自一条从没奖励过"我不知道"的训练流水线。Meta 的修法是用模型审问模型自己、对照其预训练数据来制造"我不知道"训练样本；另一个修法是给模型可以外包工作的工具。两者都有用，都不是治愈。

## 强化学习

> *"预训练读教科书，SFT 看老师解题，强化学习自己做习题。"*
> —— Karpathy

微调产出的是一个能极好地*模仿*有用助手的模型。它做不到的是发明解决问题的新办法：按构造，微调只会复现人类在训练数据里写过东西。如果从没有人类示范过某类推理，微调后的模型也不会。而对困难问题——尤其数学和编程——连人类标注员都难以写出理想解答。我们需要让模型超越它的标注员。这就是**强化学习（RL）** 的用途。

### 模仿 vs 练习

Karpathy 的类比，和每个试着给初学者讲 RL 的老师用的是同一个。想象一个孩子学解算术应用题，老师能做三件事：

1. 给孩子一本教科书读。这是预训练。

2. 坐在孩子旁边，在纸上一步步演示例题。这是监督微调。

3. 递给孩子一摞练习题，让他每道都试、对错打分，让他自己琢磨什么方法有效。这是强化学习。

前两步打基础，第三步才是技能真正砸进去的地方。看自行车视频学不会骑车，你得摔几下。对长的多步问题也没有捷径：模型必须生成许多候选解，有某种机制判定哪些走通了，然后逐渐集中到那些到达正确答案的解法上。

![RL 循环：问题提示进入模型，模型生成大量候选解，评分器判定哪些解到达了正确答案，胜者被强化，模型下次更可能产出它们。DeepSeek-R1 训练这个循环时，评分器用的仅仅是"答案对不对"。](/img/lecture-notes/images/rl_loop.png)

### RLHF 及其局限

第一个大规模部署的语言模型 RL 版本叫**基于人类反馈的强化学习（RLHF）**，出自 InstructGPT 论文，是最初 ChatGPT 成为可能的技术。配方三步：

1. 对给定提示生成少量候选回复。

2. 把候选两两一组给人类标注员看，问每组里哪个更好。

3. 训练一个较小的神经网络——**奖励模型（reward model）**——来预测标注员的偏好；然后用经典 RL 算法 PPO 微调主模型去最大化奖励模型的打分。

奖励模型是"每次都问真人"的廉价替身，让你能对数百万个提示跑这个循环而不在标注费上破产。

原论文的头条数字很震撼：一个 **13 亿参数**、用 RLHF 训练的模型，在人类偏好上赢过了 **1750 亿参数**的原味 GPT-3。小一百倍但对齐更好，就足以在真正要紧的指标上赢得正面对比。

> **注意：RLHF 的肮脏小秘密。** 奖励模型不是人，是人的有损模拟器。几百步更新之后，主模型开始找到一些怪输入：奖励模型打分很高、真人觉得莫名其妙。这是 RL 的经典失败模式——策略对抗性地钻奖励的空子。实用解法就是早停。用 Karpathy 的话说，RLHF 是"轻量版 RL"，不是真家伙。

### AlphaGo 的教训

在讲到真家伙之前，值得先知道一个下棋的故事，因为这是 Karpathy 一再回溯的类比。

2016 年 3 月，DeepMind 的 **AlphaGo** 在首尔五番棋对决韩国围棋大师**李世石**，四比一获胜。AlphaGo 有两个版本，对战李世石的那个分两阶段训练：先学人类高手的棋谱（围棋版的监督微调），再用强化学习自我对弈。一年后 DeepMind 发布 **AlphaGo Zero**，完全跳过模仿阶段，从随机落子开始纯自我对弈训练。AlphaGo Zero 比战胜李世石的那个版本强得多。去掉人类模仿，反而解锁了人类从未想过的策略。

![李世石。原书配图。](/img/lecture-notes/images/lee_sedol.jpg)

标志性例子是对李世石第二局的**第 37 手**。AlphaGo 在第五线肩冲了一手。它自己的策略网络估计人类会下这手的概率约**万分之一**。直播解说称之为失误；执黑的李世石离席平复情绪，花了超过 12 分钟应对。结果这手成了制胜手。全场从这里学到的教训是：一个愿意尝试非常规动作、并在动作奏效时获得奖励的模型，能发现确实优于人类共识的策略。

这就是 Karpathy 谈语言模型纯强化学习时压在心底的故事。

### DeepSeek-R1 时刻

2025 年 1 月 22 日——Karpathy 录制这场讲座前两周——一家叫 DeepSeek 的中国实验室发布了开放权重模型 **DeepSeek-R1**，配论文《DeepSeek-R1: Incentivizing Reasoning Capability in LLMs via Reinforcement Learning》。让论文封神的不是模型本身，而是训练配方。

DeepSeek 用**纯**强化学习训练 R1，完全没有在人类推理示范上做监督微调。对答案可验证的问题——数学、代码——奖励信号简单到极致：最终答案要么对要么不对。没有奖励模型，没有人类偏好，没有塑形。就是：给你一道题，这是正确答案，找出一条能到那儿的思维链，找到了就给奖励。

结果是一个自学一步步思考的模型。训练过程中，模型的回复自动越写越长，没人要求过它这样。它开始检查自己的工作，发现错误就回溯，说出"等等，让我重新想想"——这种短语没有任何人类在训练数据里写过。这行为纯粹从奖励信号中涌现。研究者称之为"**顿悟时刻（aha moment）**"。

如果你信 AlphaGo Zero 的教训，DeepSeek-R1 就是语言模型的同款解锁：只要时间够多、模型够大、有正确答案评分器，推理是可以教出来的。而且它落在一场 3 小时的领域讲解讲座之前两周，所以那场讲座的最后一个小时都在试图消化它。

> **2026 年 4 月更新。** 如果全书只读一条更新，读这条。2025 年 2 月到 2026 年 4 月之间，推理模型从"有希望的早期结果"变成了**前沿的主导范式**。Karpathy 结尾谨慎地说推理还"很初级"。十五个月后，它就是主线。
>
> **发生了什么。** OpenAI 的 *o1*（2024 年 9 月）和 *o3*（2024 年 12 月）证明"对思维链做 RL + 可验证奖励"在数学、科学、代码上带来巨大增益。DeepSeek 的 *R1*（2025 年 1 月，讲座录制前两周公开发布）开放复现了配方和权重。到 2025 年底，每个前沿模型都带"推理模式"：GPT-5、扩展思考的 Claude 4.x、思考型 Gemini 2.5 Pro、Grok 3 reasoning、Qwen 3 thinking。开源生态几周内跟进——DeepSeek-R1 蒸馏版、Llama 3.3 推理微调、Qwen 2.5 Math。
>
> **洞见。** 测试时算力（test-time compute）是一条**新的规模轴**。在单个问题上花 10-100 倍的推断算力，可以匹敌训练算力大 10-100 倍的模型。智能可以在训练时买（更多参数、更多数据），也可以在推断时买（每个答案更多推理 token），两者互相兑换。对难题，推断时购买往往便宜得多。
>
> **基准数字，供参照：**
>
> - **AIME 2024**（美国数学奥赛）：GPT-4o 约 12%；o3 约 96%；扩展思考的 Claude 4 Opus 约 92%。
> - **GPQA Diamond**（研究生级科学）："带 Google 的专家"约 65%；GPT-4 约 39%；o3 约 88%；Gemini 2.5 Pro 约 84%。
> - **FrontierMath**（研究级数学）：GPT-4o 约 2%；o3 在 2024 年 12 月公告时约 25%，2025 年加算力后宣称 40%+。
>
> **代价。** 推理模型更慢、每个答案更贵。拿它做摘要或闲聊是杀鸡用牛刀：标准"快"模型 2 秒作答，推理模型要想 30 秒。正确的心智模型是"难题部分用推理模型，其余用快模型"。第 11 章展开。
>
> Karpathy 方向判断对了，速度低估了。"非常初级"在大约十个月内变成了"部署在前沿"。这就是 2026 年这个领域的体感。

> **本章要点**：强化学习是模型学会*解决*问题而不仅是*模仿*解法的阶段。RLHF 对着学出来的奖励模型训练，有局限；可验证奖励的纯 RL 是 DeepSeek-R1 的配方，它让真正的推理作为涌现性质出现。这是语言模型的 AlphaGo Zero 时刻。

# 第四部分 · 使用 LLM

## LLM 如何思考（以及如何不思考）

> *"把上下文窗口当内存（RAM）用。你是操作系统。"*
> —— Karpathy

训练流水线讲完，讲座的最后一小时讲怎么用好产出的模型。Karpathy 称之为 **LLM 心理学**：这些模型的行为方式中无法从训练流程直接推出的部分，以及在你把要紧事托付给它之前值得了解的失败方式。

### 两种记忆

用好 LLM 最重要的区分，是模型具有的两种记忆。

**长期记忆**住在**参数**里。预训练中学到的一切被压缩进数千亿个训练结束后永不改变的数字。模型因此"知道"法国首都是巴黎、Python 的 `for` 循环长什么样。它海量但有损：一个具体事实可能出得略有偏差，就像你可能记错十年前读过的某本书的细节。

**工作记忆**是**上下文窗口（context window）**：模型当前正看着的 token 列表——你的提示词、附上的文件、以及助手自己此前的回复。这份记忆是清晰的：模型对窗口里的每个 token 都有逐字的、精确的访问。上下文窗口里有什么，就能以完美保真度取用什么。

> **旁注：一条回报率极高的习惯。** 想让模型处理某份具体文档，就把文档贴进提示词。不要说"总结一下关于 X 的那篇 2023 年论文"，要说"这是关于 X 的 2023 年论文，请总结"，然后把文本附上。所有可度量的准确率指标都会上升。这是我所知的日常使用中最大的单项收益。

Karpathy 的类比是计算机的 **CPU 和内存**：参数是硬盘——海量信息，取回慢且有损；上下文窗口是内存——少量信息，即时且完美地访问。而你，用户，是操作系统：决定任何给定任务往内存里装什么。

### 模型需要用来思考的 token

模型每处理一个 token，就发生固定量的计算。如果你强迫模型用一个 token 吐出答案，它必须把全部推理塞进一遍前向传播。对任何不平凡的问题，算力都不够，模型就会失败。如果让它先写出思考过程，每个中间 token 都给它多一遍前向传播可用。

**"让我们一步步思考"** 不只是礼貌性提示词，它在字面意义上给了模型更多算力——强迫它产出更多 token。这也是为什么现代推理模型在给出最终答案前有一段可见的长"思考"（DeepSeek 和 OpenAI o1 上都看得到）：思考阶段的每个 token 都是一份额外的算力。模型确实是在通过多写来更努力地想。

### 能力是锯齿状的

把要紧事交给 LLM 之前要内化的最后一课：它的能力是**锯齿状（jagged）** 的。模型能解博士级物理题，然后比较不了 9.11 和 9.9；能写出像样的法律文书，然后数错 strawberry 的字母；能把三羧酸循环讲得滴水不漏，然后算错一道基础乘法。从模型的训练方式看，这些失败没有一个是"蠢"——它们只是不均匀地散布在任务空间里，分布方式与人类直觉不符。

> **注意：永远不要因为模型做对过难题就信任它。** 依赖它做要紧事之前，先跑几个小的 sanity check：让它做你能验算的算术，让它引用你能查证的来源。把它当天赋异禀的实习生，不是神谕。让它做擅长的部分，对可疑的部分加倍检查。

> **本章要点**：模型有两种记忆：上下文窗口清晰，参数模糊——优先用前者。给模型用来思考的 token。并记住能力是锯齿状的——它刚做对一道难题这件事，对下一题毫无保证。

## 实践建议

> *"信任，但要验证。"*
> —— 里根，以及每个我敬重的 LLM 用户

下面大部分是我在讲座里捡到的习惯，加上自己日用这些模型攒下的经验。单独看没有一条惊人，加总起来却比"随手问 ChatGPT 然后祈祷"好出一大截。

### 选模型

凡是涉及数学、代码、逻辑或多步规划的，用**推理模型**：DeepSeek-R1、OpenAI o1、开了扩展思考的 Claude、Gemini Deep Research。它们更慢更贵，但在难题上的准确率差异很大。写作、总结、头脑风暴、一般知识问答，用**标准模型**（GPT-4o、Claude Sonnet、Gemini Flash）就够，而且快得多。

如果有本地跑模型的理由——隐私或成本——用 **LM Studio** 或 **Ollama**。你追不上前沿，但会得到快速、离线、免费。Llama 3、Gemma 的蒸馏量化版和小号 DeepSeek-R1 变体，在 16 GB 内存加中端 GPU 的笔记本上跑得出奇地好。

### 高效使用 LLM 的七个习惯

1. **把事实放进提示词。** 我所知的最大准确率收益。贴文档，别信记忆。

2. **要求它一步步想。** 免费。对一切受益于中间推理的东西，准确率翻倍。

3. **让它用工具。** 计算器、代码解释器、网页搜索。界面有"代码解释器"或"浏览网页"选项的，凡涉及数字、近期事件、引用就打开。

4. **给它角色。** "你是资深 Python 工程师，评审这个 PR"稳定产出比"请评审这个 PR"更好的代码评审。

5. **验证要紧的。** 读引用的来源，跑生成的代码，核对数字。模型是研究助理，不是审计师。

6. **要短上下文，不要长上下文。** 保持对话聚焦。上下文窗口一旦填满，模型会悄悄丢掉较早的材料。

7. **答案可疑时，它多半真可疑。** 对冷门之物的自信精确是幻觉的签名。拿不准就换个问法问两遍，对比。

> **2026 年 4 月更新。** 讲座之后有三个实务变化值得并入你的心智模型：
>
> **上下文窗口大得多。** Karpathy 拍摄时前沿是 128K-200K token；2026 年 4 月，Gemini 2.5、Claude 4 Opus、GPT-5 都有 1M+ 上下文，全窗口"大海捞针"召回接近 99%。实际含义：现在可以贴一整本 900 页的 PDF，并指望模型记得第 847 页。但每个 token 都要付钱，保持对话聚焦的习惯仍然是对的。
>
> **Agentic 编程工具自立门类。** Cursor Composer、Claude Code、Cognition 的 Devin、OpenAI Codex，都让推理模型在真实代码库上规划、编辑、运行、迭代，带终端和文件系统访问。它们不再是自动补全，能自主完成数小时的任务。任务若是"改这个函数、让测试通过"，这类工具通常一个提示就能搞定；任务若是"从零设计一个新服务的架构"，你仍然要自己来，但 agent 很乐意实现你specify好的部分。
>
> **"推理 vs 快速"是选型的正确心智模型。** 凡涉及数学、代码、逻辑、多步规划，为推理模型多付延迟；闲聊、摘要、写作辅助，快模型更便宜、更迅速、一样好。多数前沿产品现在有显式开关，选对。

> **本章要点**：LLM 奖励细心的用户。按任务选模型，把事实放进提示词，让模型把思考说出来，给它工具，验证一切要紧的东西。这些习惯不能消灭错误，但能大幅削减。

## 2025 年 2 月以来

> *"领域跑得快。2026 年写的、关于 2025 年讲座的笔记，唯一的诚实方式就是说明此后变了什么。"*
> —— 作者

这一章是全部其他章节写完后补的。它把 Karpathy 拍摄讲座之后的十四个月里 LLM 版图上发生的最重要的事收在一处。书中那些"2026 年 4 月更新"框在需要更新具体细节时都指回这里；本章是结构化汇总。

我刻意保持简短。讲座仍然是对"LLM 如何构建"近乎完美的讲解，其中 80% 今天依然精确成立。剩下 20% 收在下面。

### 新的前沿模型

Karpathy 的参照系是 GPT-4、Claude 3.5 Sonnet、Llama 3、Gemini 1.5 和 DeepSeek-R1。2026 年 4 月的阵容：

- **OpenAI**：**GPT-5**（2025 年 8 月）是现任旗舰，一个统一的具备推理能力的模型，取代了 *o1*/*GPT-4o* 的双轨。*o 系列*仍作为高推理预算的专属模式存在。
- **Anthropic**：**Claude 4 Opus**（2025 年中）与 **Claude 4 Sonnet**（2025 年底）加入扩展思考、Computer Use 和 1M token 上下文窗口。写作时最新版是 Claude 4.6 Opus。
- **Google**：**Gemini 2.5 Pro** 与 **Gemini 3**（2026 年初）带推理模式，维持 1M+ 上下文。Gemini 2.0 Flash 仍是快速档。
- **Meta**：**Llama 4 Scout** 与 **Llama 4 Maverick**（2025 年初）让 MoE 在开放权重世界成为主流。**Llama 4 Behemoth**（据传约 2 万亿总参）是内部前沿。
- **DeepSeek**：**DeepSeek-V3**（671B MoE，37B 激活）与 **DeepSeek-R1**（开放推理模型）在 2025 年初一个月内先后落地，迫使每个前沿实验室重新审视自己的护城河。DeepSeek-V3 训练成本约 600 万美元 GPU 时。
- **xAI**：**Grok 3**（2025）与 **Grok 4**（传，2026）带着自己的推理模式和超大训练集群入场。
- **Mistral、Qwen、Cohere、01.ai、Kimi**：第二梯队实验室持续产出有竞争力的开放权重模型，尤其在 70B-200B 参数区间。

### 推理模型：主事件

推理模型的崛起是讲座与今天之间最大的单一变化。Karpathy 的 *DeepSeek-R1* 一节是种子，整棵树从它长出来。

推理模型是被训练成在给出最终答案前先写一长串思维链（数万 token 常见）的模型。训练混合了两样东西：推理轨迹的监督数据，加上答案正确性可自动验证任务的 RL——数学题、能跑的代码、有已知解的谜题。奖励是答案，不是路径；路径模型自己找。

关键基准把故事讲得很干净：*AIME 2024* 上，GPT-4o 这类标准模型约 12%，o3 与 Claude 4 Opus 90% 以上；*GPQA Diamond*（研究生级科学）上标准模型 40% 左右，推理模型 85% 以上；*FrontierMath*（现存最难的数学基准）上 o3 在 2024 年 12 月破 25%，2025 年中加算力破 40%。作为参照：这个基准的设计目标就是让 2024 年前的任何模型无解。

实务结论：做任何像*解题*的事，用推理模型；做任何像*文本塑形*的事（总结这篇文档、写这封邮件、改写这段话），快模型足矣。

### 上下文长度与检索

2024 年由 Gemini 1.5 Pro 首创的 1M token 前沿上下文窗口，如今是常态而非例外。Claude 4、Gemini 2.5、GPT-5 都能可靠处理 1M token，*大海捞针*基准上接近完美召回（在百万 token 里埋一个事实，让模型去找）。

实际后果是"把整个仓库装进来再提问"成了合理工作流。RAG 对企业知识库仍然值得做，但"全贴进提示词"和"搭一套 RAG 系统"的边界已大幅向前者移动。剩下唯一的约束是成本账。

### 多模态成为默认

Karpathy 讲座里模型仍以文本为主、可选图像输入。到 2026 年：

- **对话模型内的原生图像生成**（GPT-4o 图像生成、Gemini 2.0 图像输出）在多数产品里取代了独立的"图像模型"。
- **视频理解**（逐帧真处理，不只是抽帧）在 Gemini 成了标配，Claude 4 也有。
- **语音模式**在 ChatGPT、Claude、Gemini 上达到对话级延迟和近人声韵律。这是完全不同的交互模态，不是文本模型套 TTS。
- **音频输入**包括音乐和非语音音频，多数前沿模型已能理解。

这一切底下的架构仍是 Transformer 加上给非文本 token 的额外嵌入/解码头。Karpathy 的"一切都是 token"的框架依然成立——只是现在 token 的种类更多了。

### Agent 与编程革命

2024 到 2026 年间，*agentic 编程*从演示变成日用品。几个值得认识的产品：

- **Cursor Composer**：把推理模型集成进真实编辑器，带全代码库上下文。默认模式已是多文件、多步骤，模型自己跑终端命令。
- **Claude Code**：Anthropic 自家的 CLI。给它任务，它改文件、跑测试、迭代直到测试通过。正是这个工具在写本项目的几个脚本。
- **Cognition Devin**：炒作最响的"自主工程师"产品，已在多家公司用于可重复的维护任务。
- **OpenAI Codex**：2025 年以推理编程 agent 的身份重新发布；GitHub Copilot Workspaces 是 GitHub UI 里的同一思路。

这些都不取代人类工程师的判断，但它们取代了过去填满工程师一天的大量*打字*。保守估计的比例大约是 1 小时人的思考兑 3-5 小时机器实现。这是版本控制以来工程工作最大的生产力变化。

### 硬件：Blackwell 和朋友们

2025-2026 年这代 GPU 是 NVIDIA 的 **Blackwell**：*B100*、*B200* 和 *GB200* NVL72 机架系统。每张 B200 的训练吞吐约为 H100 的 2.5 倍；GB200 NVL72 把 72 张 B200 合成一个整体单元，用于超大模型训练。

竞争芯片：AMD 的 *MI300X* 是推理侧的正当备选；Groq 的 *LPU* 是特定模型上金钱能买到的最快推理芯片；Cerebras WSE-3 用整片晶圆服务特定负载；Google 内部训练继续用自己的 TPU v5p 和 v6。

对不自建数据中心的人，直接含义很小，但推断的**每 token 成本**在讲座拍摄后的 18 个月里降了约 5-10 倍。这正是 Cursor 和 Claude Code 在经济上成立、而 2024 年初还不成立的原因。

### Karpathy 说对的那些 100% 仍然对的东西

要说清楚：讲座的压倒性多数内容完美地老了。基本盘没变：

- token 仍然不透明。strawberry 问题仍在，虽然推理模型常能绕开。
- Transformer 仍是骨干。MoE 是前馈层内部的改良，不是新架构。
- 训练流水线仍是预训练 → SFT → RL。上面加的一切都装在这三个阶段之一里。
- 基座模型仍是文档模拟器，不是聊天机器人。hyperbolic.xyz 那个 demo 仍是亲眼见证的最毛骨悚然的方式。
- 幻觉仍是真问题。护栏更好了，但它们发生的统计原因没变。
- 第 11 章的实务习惯（事实进提示词、要求推理、用工具、验证）仍然完全正确。

如果你内化了讲座，本章的一切都自然叠在它上面。对一个跑得这么快的领域里的讲解而言，这是最高级别的赞美。

> **本章要点**：讲座之后的十四个月里，最大变化是推理模型的崛起。上下文窗口变得巨大，MoE 成为主流，多模态成为默认，agentic 编程工具是今年的生产力意外。底层流水线没有变。

## 术语表

**Attention（注意力）**——让序列中每个 token 看向所有其他 token、并决定每个 token 对计算自己下一层表示有多重要的机制。

**Base model（基座模型）**——预训练结束、任何微调开始之前的模型。行为像文档模拟器，不像对话伙伴。

**BPE（Byte-Pair Encoding，字节对编码）**——构建 token 词表的算法。从单个字节出发，迭代地把最高频相邻对合并成新 token，直到达到目标词表大小。

**Common Crawl**——下载公开网页并免费发布的非营利组织。几乎所有 LLM 训练数据集的起点。

**Context window（上下文窗口）**——模型当前能看到的 token 列表：你的提示词加对话此前的轮次。现代 LLM 的上下文窗口从 10 万到数百万 token。

**Embedding（嵌入）**——一个稠密的数字向量，以神经网络能做算术的形式表示一个 token 的含义。

**FineWeb**——Hugging Face 从 Common Crawl 衍生的开放 15 万亿 token 数据集。前沿实验室内部所建数据的最干净的公开类似物。

**Hallucination（幻觉）**——LLM 听起来自信但事实上错误的输出。

**LLM（大语言模型）**——基于 Transformer 的神经网络，通常有数十亿参数，在海量文本上训练来预测下一个 token。

**Parameters（参数）**——模型内部可训练的数字。GPT-4 据传约一万亿个。

**Pre-training（预训练）**——训练第一阶段：模型阅读海量互联网文本学习预测下一个 token。产出基座模型。

**DPO（Direct Preference Optimization，直接偏好优化）**——2023 年提出的 RLHF 简化替代：给定偏好与非偏好答案对，用分类损失直接调整策略，跳过独立的奖励模型阶段。2024 到 2026 年间成为标准偏好训练方法。

**MoE（Mixture of Experts，专家混合）**——Transformer 变体：前馈层由许多更小的"专家"子层构成，路由器为每个 token 挑选少数几个。把总参数量与每 token 算力解耦。Llama 4、DeepSeek-V3、Mixtral 及若干前沿闭源模型在用。

**Reasoning model（推理模型）**——被训练成（通常用 RL）在给出最终答案前写长思维链的语言模型。例：OpenAI o1/o3、DeepSeek-R1、思考型 Gemini 2.5 Pro、扩展思考的 Claude 4 Opus。在答案可验证的问题（数学、代码）上强得多；每个回复更慢更贵。

**RAG（Retrieval-Augmented Generation，检索增强生成）**——先生成前检索相关文档的模式，让模型从检索到的文本而非参数中作答。减少幻觉，让同一个模型能处理私有或新更新的知识。

**RLHF（Reinforcement Learning from Human Feedback）**——基于人类反馈的强化学习。InstructGPT 论文引入的具体配方：收集人类偏好排序，训练奖励模型，用 PPO 对着奖励模型优化。

**SFT（Supervised Fine-Tuning，监督微调）**——训练第二阶段：基座模型在人类书写的示例对话上微调。把文档模拟器变成助手。

**Token（词元）**——一小段文本（通常几个字符），带唯一整数 ID。LLM 读写的原子单位。

**Test-time compute（测试时算力）**——训练规模在推断侧的对应物：每个答案花更多算力（更长思维链、更多候选采样、自一致性）可以替代更大的模型。推理模型背后的主杠杆。

**Tool use（工具使用）**——让 LLM 在生成过程中调用外部工具（计算器、代码解释器、搜索引擎、API）的模式。把知识问题转化为阅读理解问题，消灭许多类幻觉。

**Transformer**——每个现代 LLM 背后的神经网络架构。出自 2017 年论文《Attention Is All You Need》。
